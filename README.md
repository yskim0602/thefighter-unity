# TheFighter (더 파이터) — Unity

성장형 복싱 게임 「더 파이터」. **Unity 프로젝트 (독립 저장소)**

**목표 플랫폼: 모바일(App Store / Play Store).** 기본 입력은 터치, 기본 시점은
링사이드를 천천히 도는 브로드캐스트 카메라입니다. 키보드·1인칭은 PC에서
빠르게 테스트하기 위한 보조 경로로 남겨뒀습니다.

이전에 Godot로 만든 프로토타입([yskim0602/thefighter](https://github.com/yskim0602/thefighter))은
기획과 전투 시스템을 검증하는 용도였고, 이 저장소와는 **완전히 별개**입니다.
코드를 기계적으로 변환한 게 아니라, 거기서 확정된 기획을 Unity에 맞는 구조로
다시 설계했습니다 (2절 참고).

## 1. 확정된 기획

**장르**

- MMA가 아닌 **복싱**. 발차기·그래플링 없음
- 전투만큼이나 **성장(커리어)**이 축: 파이트머니로 능력치를 올리고 무대를 올라감
- 지금은 그래픽 품질이 아니라 **실제 복싱 플레이와 타격감**이 우선.
  캐릭터는 캡슐/구 프리미티브 그대로, 실제 모델은 재미가 확인된 뒤에
- **1인칭 복싱을 우선 테스트**

**전투**

| 요소 | 내용 |
| --- | --- |
| 펀치 | 잽 / 스트레이트 / 훅 / 어퍼컷 — 데미지·스태미나·선딜·사거리·가드 관통이 전부 다름 |
| 손 | 양손 글러브. 잽·훅은 앞손, 스트레이트·어퍼컷은 뒷손 |
| 스탠스 | 오소독스 / 사우스포. 앞손·뒷손과 좌우 위치·궤적이 전부 거울상으로 반전 |
| 가드 | 데미지 대폭 감소 + **가드 게이지**. 0이 되면 강제 가드 브레이크(1.5초) |
| 회피 | 짧은 슬립. 스태미나 소모, 쿨다운 있음, 완전 무적은 아님 |
| 스태미나 | 체력과 별개 자원. 연타할수록 소모 증가, 바닥나면 데미지↓ 쿨다운↑ |
| 피격 부위 | 머리(확률적 경직) / 몸통(스태미나 추가 감소) |
| 카운터 | ① 퍼펙트 블록·회피 직후 ② 상대 펀치 선딜(무방비) 처벌 — 두 경로 |
| 다운/KO | 3-다운제. 다운 시 카운트, 펀치 버튼 연타로 빨리 일어남, 3번째 다운은 KO |
| 스타일 | 아웃복서 / 인파이터 / 슬러거 / 복서-펀처 / 카운터펀처 / 프레셔 파이터 6종 |

**스타일 규칙** — 능력치 위에 곱연산으로 얹힘. CPU는 경기 중 상황에 따라
실시간 전환(초반 아웃복서 → 체력 위험 시 인파이터 → 피격 직후 카운터펀처).
플레이어는 스타일을 고르지 않고, 훈련한 능력치 분포에서 자동으로 추론됨.

**커리어 구조** (아직 미구현, 기획은 확정)

홈 → FIGHT → **경기 제의** → 수락/거절 → 경기 → 결과 → 커리어 반영.
상대와 무대를 직접 고르지 않고 게임이 제의를 보냄. 스테이지 1~6은 승수 기반
(10경기 7승 → 승급전), 7~10은 랭크 기반(30 → 1 → 타이틀전 → 방어전).

## 2. Godot 버전과 다르게 설계한 부분

| # | Godot 버전 | Unity 버전 | 왜 |
| --- | --- | --- | --- |
| 1 | `Fighter.gd` 베이스 클래스를 `PlayerController`/`AIController`가 **상속** | `Fighter` + `IFighterBrain`(`PlayerBrain` / `AIBrain`) **컴포지션** | 상속은 "누가 조종하는가"를 타입에 박아버림. 브레인을 분리하면 같은 파이터에 AI를 붙여 AI vs AI 밸런스 테스트, 리플레이, 스파링 모드가 전부 공짜로 열림 |
| 2 | 머리/몸통을 **펀치별 확률**로 굴림 | 실제 **히트박스 2개**(머리 구 / 몸통 캡슐)에 글러브를 오버랩 | 1인칭이 주력이면 "내가 조준한 곳에 맞는다"가 핵심. 마우스를 내리면 보디, 올리면 헤드 — 확률이 아니라 플레이어의 선택이 됨 |
| 3 | 거리 기반 히트 판정 | 글러브 트랜스폼 위치로 판정 | 보이는 글러브가 곧 히트박스. 모션과 판정이 어긋나지 않음 |
| 4 | `.tscn` 씬 파일에 노드 배치 | `BoxingBootstrap`이 **코드로 씬을 구성** | 씬 파일은 diff도 리뷰도 머지도 안 됨. 프로토타입 단계에선 코드가 훨씬 빠름 (에디터 메뉴로 씬 생성 지원) |
| 5 | 글러브가 1인칭에서 화면을 다 가림 | 1인칭 **전용 포즈 세트** + 축소 스케일 | 4절 참고 |
| 6 | 스타일 전환이 최대 체력에도 영향 | `SetBaseStyle`(풀 결정) / `SetActiveStyle`(전술 전환) 분리 | AI가 인파이터로 바꿀 때 최대 체력이 같이 흔들리면 안 됨 |
| 7 | `CareerConfig.gd`에 수치 집중 | `CombatTuning.cs` + `BoxingStyles.cs`에 집중 | 이 방식은 좋았으니 유지. 밸런스는 이 두 파일만 건드림 |

## 3. 실행 방법

1. 이 저장소를 클론 (또는 ZIP을 원하는 위치에 압축 해제)
2. Unity Hub → **Installs** 탭에서 에디터가 없으면 설치 (Unity 6000.0 LTS 권장,
   2021.3 이상이면 다른 버전으로 열어도 됩니다)
3. Unity Hub → **Projects** → 오른쪽 위 **Add** → *Add project from disk* →
   **클론한 폴더 자체**를 선택 (`Assets` 폴더가 보이는 그 위치)
4. 프로젝트를 열기 — 처음 열 때 `Library/`, `Packages/`, 나머지
   `ProjectSettings/`를 Unity가 기본값으로 생성하므로 몇 분 걸립니다
5. 상단 메뉴 **The Fighter → Create Boxing Prototype Scene**
6. **Play** ▶

씬을 만들지 않고 직접 해도 됩니다: 빈 씬에 빈 GameObject 하나 만들고
`BoxingBootstrap` 컴포넌트만 붙이면 나머지(링·조명·양 선수·카메라·HUD)는
전부 실행 시점에 자동 생성됩니다.

> 만약 `Input.GetKey` 관련 에러가 나면 Project Settings → Player →
> **Active Input Handling**을 `Input Manager (Old)` 또는 `Both`로 바꿔주세요.
> 이 프로토타입은 의도적으로 구버전 입력을 씁니다(패키지 의존성 0).

## 조작법 — 터치 (모바일, 기본)

가로 화면 기준. 양쪽 엄지가 닿는 자리만 쓰도록 배치해서, 어느 쪽도 손을
뻗을 필요가 없습니다.

| 조작 | 동작 |
| --- | --- |
| **왼쪽 영역 드래그** | 플로팅 스틱. 처음 닿은 지점이 중심. 전진/후진/서클링 — **항상 상대 기준** |
| **오른쪽 영역 탭** | 왼쪽 절반 = 잽(앞손), 오른쪽 절반 = 스트레이트(뒷손) |
| ↑ **탭 위치가 높으면 헤드 / 낮으면 보디** | 마우스 조준을 터치로 옮긴 것. **탭한 곳으로 펀치가 갑니다** |
| **위로 스와이프** | 어퍼컷 |
| **좌우로 스와이프** | 훅 |
| **아래로 스와이프** | 회피(슬립) |
| **길게 누르기** | 가드 (떼면 바로 내려가고, 펀치를 내면 자동 해제) |
| 다운 중 탭 | 마샤 — 일어나는 시간 단축 |

스와이프 거리는 `Screen.dpi` 기준 인치로 계산하므로 기기가 바뀌어도 같은
손동작입니다. 영역·임계값은 `TouchBrain` 인스펙터에서 실행 중 조정 가능합니다.

**에디터에서 터치 테스트**: `BoxingBootstrap` → `Controls`를 `Touch`로 바꾸면
마우스가 손가락 하나를 대신합니다(손가락이 하나뿐이라 이동과 펀치 동시 입력은
안 됩니다 — 제스처 인식 확인용). 화면에 영역·분할선·스틱이 오버레이로 표시됩니다.

## 4. 1인칭 글러브 — 화면을 가리던 문제

> 1인칭은 이제 기본 시점이 아닙니다(5절의 브로드캐스트 카메라가 기본). 이 절의
> 해법은 PC 1인칭에서 유효한 것이고, **폰에서는 바로 이 위치가 엄지 밑에 깔립니다.**
> 1.5단계 실기기 검증에서 1인칭을 유지할지 결정해야 합니다.

Godot에서 1인칭으로 플레이했을 때 글러브가 화면의 너무 많은 부분을 차지해서
상대가 안 보이는 문제가 있었습니다. 원인은 **3인칭용 글러브 위치를 1인칭에서
그대로 썼기 때문**입니다. 눈높이 카메라에서 팔 길이만큼 떨어진 구는 화면
높이의 절반을 그냥 먹습니다.

이 버전은 `GloveRig`가 **시점별로 다른 rest 포즈 세트**를 씁니다:

| | 평소(idle) | 가드 |
| --- | --- | --- |
| 화면상 위치 | 화면 **아래쪽 가장자리**에 살짝 걸침 | 중앙선 근처까지 올라와 시야를 감쌈 |
| 가운데 시야 | 완전히 비어 있음 | 두 글러브 사이에 틈이 남음 (피카부 가드) |

추가로 1인칭일 때는 글러브 스케일 자체를 **0.62배**로 줄입니다.

```
FirstPersonIdleLead   (0.20, 1.41, 0.50)   // 눈(y=1.62) 기준 22cm 아래
FirstPersonIdleRear   (0.27, 1.38, 0.44)
FirstPersonGuardLead  (0.14, 1.56, 0.42)   // 눈 기준 6cm 아래까지 올라옴
FirstPersonGuardRear  (0.18, 1.52, 0.38)
FirstPersonGloveScale 0.62
```

**중요**: 이 포즈는 *평소 자세*에만 적용됩니다. 펀치를 뻗는 동안 글러브는
실제 궤적(어깨 → 조준점)으로 수렴하기 때문에, **1인칭과 3인칭의 펀치가
닿는 위치는 완전히 동일**합니다. 보기 좋게 낮췄다고 펀치가 짧아지지 않습니다.

튜닝은 실행 중에 바로 할 수 있습니다 — Hierarchy에서 플레이어 오브젝트 →
`Glove Rig` 컴포넌트의 값을 Play 모드에서 바꾸면 즉시 반영됩니다.
마음에 드는 값을 찾은 뒤 `GloveRig.cs`의 기본값에 옮겨 적으면 됩니다.

## 5. 카메라 — 브로드캐스트 뷰

기본 시점은 고정 카메라가 아니라, 링사이드에서 **천천히 호를 그리며 움직이는
중계 카메라**입니다 (Tactic Boxing / Boxing Simulator 계열의 연출).

- **궤도 드리프트**: 플레이어 등 뒤를 기준으로 ±32° 범위 안에서 목표 각도를
  랜덤하게 잡고 천천히 이동합니다. 도착하면 잠시 머물다 다음 각도로 — 카메라맨이
  자리를 옮기는 리듬입니다
- **거리 호흡**: 두 선수가 붙으면 당겨지고(2.45m), 벌어지면 물러납니다(3.95m)
- **푸시인**: 다운·카운터·클린히트에서 순간적으로 파고듭니다 (`PushIn()`)
- **다운 추적**: 누군가 쓰러지면 시선이 그쪽으로 기울어집니다

**호를 ±32°로 제한한 이유**: 풋워크가 카메라가 아니라 **상대 기준**이기 때문입니다.
카메라가 상대 뒤까지 돌아가면 플레이어의 "왼쪽으로 서클링"이 화면에서는 오른쪽으로
보여서 조작이 뒤집힙니다. 한쪽 사이드에 머무르는 건 실제 링사이드 카메라가 하는
방식이기도 합니다.

1인칭은 `V`로 전환되고, 터치 환경에서는 조준을 `TouchBrain`이 담당하므로
카메라에 의존하지 않습니다.

## 6. 스탯 밸런스

네 가지 스탯이 각각 **눈에 보이는 하나**를 담당합니다. 수치표를 안 봐도 상대가
어떤 선수인지 싸우는 중에 읽히는 게 목표입니다.

| 스탯 | 담당 | 공식 |
| --- | --- | --- |
| **파워** | 펀치 데미지 | `5 + Power × 0.85` |
| **체력(Endurance)** | 체력 풀 + 스태미나 풀 | `70 + End × 5.5` / `60 + End × 2.5 + Skill × 1.5` |
| **스피드** | 풋워크 + **펀치가 나가는 속도**(선딜·타격) | `1.8 + Spd × 0.075` / `1 / (0.80 + Spd × 0.020)` |
| **스킬** | **펀치 회수 속도**(후딜) + 리치 | `1 / (0.85 + Skill × 0.015)` / `0.70 + Skill × 0.0025` |

스피드와 스킬을 나눈 게 핵심입니다. **스피드는 주먹이 빨리 나가고, 스킬은 빨리
돌아옵니다** — 그래서 스킬이 높은 선수는 단순히 빠른 게 아니라 "빈틈을 안 주는"
선수가 됩니다 (빈틈 카운터가 바로 후딜을 노리는 판정이라 체감이 직접적입니다).

**체력바는 정규화하지 않습니다.** 공용 기준값(`CombatTuning.HealthBarReference`)에
대고 그리기 때문에, 체력 스탯이 높은 선수는 **바 자체가 더 깁니다**. 바의 *길이*는
풀, *채워진 양*은 남은 체력입니다. 뒤에 희미한 전체 트랙이 같이 그려져서 두 선수를
바로 비교할 수 있고, HP 숫자도 함께 표시됩니다.

스타일 배율(`BoxingStyles`)은 이 위에 곱연산으로 얹히고, **최대 체력·스태미나는
입장할 때의 스타일(`SetBaseStyle`)만 결정**합니다 — AI가 경기 중 인파이터로
바꿔도 바가 흔들리지 않습니다.

## 7. 경기 규칙 — 라운드와 판정

복싱의 **구조**는 그대로 가져왔습니다. 공, 라운드별 페이스 배분, 코너, 내가
지고 있을 수 있는 채점표 — 이게 "경기를 뛴다"는 느낌의 전부입니다.
**시간만 압축**했습니다. 실제 12라운드 타이틀전은 47분이고, 그걸로는 커리어를
돌릴 수 없습니다.

| | 값 | 이유 |
| --- | --- | --- |
| 라운드 길이 | **90초** | 실제의 절반. 페이스·가스 배분이 실제 판단이 되고 공이 반가울 만큼은 길지만, 한 라운드가 늘어지지는 않는 길이 |
| 라운드 휴식 | **12초** | 실제 1분에서 압축. 채점표 읽고 숨 돌릴 만큼. 나중에 코너 연출·세리머니가 들어갈 자리 |
| 경기 전 | 2.5초 | 개시 공 (추후 입장 연출 자리) |

**경기 거리는 커리어 단계에 따라 늘어납니다** (`RoundRules.RoundsForStage`).
복싱이 실제로 그렇고, "진짜 선수가 되는 느낌"도 거기서 나옵니다 — 데뷔전은
지치기도 전에 끝나고, 타이틀전은 버텨내야 하는 시련입니다.

| 커리어 단계 | 라운드 | 총 길이(휴식 포함) |
| --- | --- | --- |
| 1~2 (언더그라운드·아마추어) | 3 | 약 4.9분 |
| 3~4 (루키·파이트리그) | 4 | 약 6.6분 |
| 5~6 (엘리트·월드시리즈) | 5 | 약 8.3분 |
| 7~8 (랭크·TOP 10) | 6 | 약 10분 |
| 9~10 (타이틀샷·챔피언십) | 8 | 약 13.4분 |

### 채점 — 10점 머스트, 심판 3명

`Scorecard.cs`. 라운드마다 세 심판이 **독립적으로** 채점합니다.

- 각 심판은 **클린 펀치 / 유효타 수 / 방어(블록·슬립) / 다운**에 대한 가중치가
  서로 다르고, 매 경기 새로 뽑힙니다. 여기에 약간의 노이즈가 붙습니다
- 이긴 쪽 10점, 진 쪽 9점. 격차가 거의 없으면 **10-10**
- **다운당 1점 차감** → 10-8, 두 번이면 10-7
- 판정: **만장일치 / 스플릿 / 다수 / 무승부**

가중치가 심판마다 다른 게 핵심입니다. 같은 경기가 카드마다 다르게 적히고,
접전 라운드가 실제로 흔들리고, **스플릿 판정**이 나옵니다 — 마지막 라운드를
남기고 카드상 2라운드 뒤져 있다는 감각이 이 시스템이 존재하는 이유입니다.

### 코너 회복과 3-다운제

- 복싱에선 회복이 없지만, 아무것도 안 돌려주면 매 경기 TKO로 끝나고 채점표가
  무의미해집니다. 그래서 **코너가 조금 돌려줍니다** — 스태미나는 많이,
  체력은 조금
- **경기가 깊어질수록 코너 효과가 줄어듭니다**(`RestHealthFade`).
  그래서 후반 라운드가 무섭습니다
- 아무리 두들겨 맞았어도 최소 22%는 들고 다음 라운드에 나갑니다. 공에 살아난
  선수가 다음 라운드 첫 잽에 또 다운되는 걸 막는 장치입니다
- **3-다운제는 같은 라운드 기준**입니다(실제 규칙대로). 라운드가 바뀌면
  카운트가 초기화되고, 경기 전체의 다운은 **점수로** 남습니다
- 라운드 종료 공이 울리면 카운트가 멈춥니다 — "공에 살았다". 단 그 다운은
  채점표에 그대로 남습니다

## 8. 타격감 — 어디서 나오고 어떻게 만지는지

타격감은 한 가지가 아니라 **여러 층이 동시에 터지는 것**입니다. 지금 들어간 층:

| 층 | 무슨 일이 | 어디 |
| --- | --- | --- |
| **피격 반응** | 맞은 쪽 몸이 실제로 움직임. 머리샷은 머리가 뒤·옆으로 꺾이고, 보디샷은 몸이 접힘 | `FighterRig.PlayHitReaction` |
| **글러브 정지** | 명중 순간 스트라이크를 끊고 바로 후딜로 — 주먹이 상대를 통과하지 않음 | `Fighter.AdvancePunch` |
| **몸의 커밋** | 펀치마다 상체가 감겼다 풀리고 어깨가 돌아가며 앞으로 밀고 나감 | `FighterRig.UpdateBody` |
| **히트스톱** | 접촉 순간 `Time.timeScale`을 떨어뜨림 (클린 65ms / 블록 28ms / 다운 180ms) | `ImpactFeedback.Freeze` |
| **카메라** | 흔들림 + FOV 킥 + 브로드캐스트 푸시인. **때릴 때도** 작게 킥이 들어감 | `FightCamera` |
| **화면 플래시** | 내가 맞으면 화면 전체가 붉게 물듦 — 3인칭에선 이게 없으면 맞은 걸 못 느낌 | `FightHud.DrawDamageFlash` |
| **소리** | 절차 생성 타격음. **펀치 무게에 따라 피치가 달라짐** (잽은 높고 어퍼컷은 낮음) | `ImpactFeedback.PlayPunch` |
| **넉백** | 관통 데미지만큼 밀림 (이전보다 약 2배로 올림) | `CombatTuning.KnockbackPerDamage` |
| **다운 포즈** | 무릎을 꿇듯 몸이 주저앉음. 이전엔 다운돼도 그냥 서 있었음 | `FighterRig.DownPosition/DownRotation` |

### 콤보 규칙 — 이번에 들어간 가장 큰 변화

전에는 한 펀치가 **완전히 끝나야** 다음 펀치가 나갔습니다. 그래서 원투가 안 되고
단발만 나갔습니다. 이제:

- 후딜의 **55%** 지점부터 다음 펀치로 **캔슬** 가능 (`ComboCancelFraction`)
- 단, **반대 손만** 가능 — 같은 글러브로 연사가 안 됩니다
- 캔슬하면 스태미나를 **1.35배** 더 씁니다

그래서 **잽(앞손) → 스트레이트(뒷손)** 가 자연스럽게 흐르고, 잽 연타는 막힙니다.
이 규칙 하나가 "펀치를 던지는 것"과 "복싱"의 차이를 만듭니다.

### 튜닝 표 — 느낌이 안 맞을 때 만질 곳

**Play 모드에서 실시간으로 바꿀 수 있는 것** (Hierarchy에서 선수 오브젝트 선택
→ `Fighter Rig` 컴포넌트):

| 증상 | 노브 |
| --- | --- |
| 맞는 반응이 약함 / 과함 | `RecoilDamageReference` (낮추면 강해짐), `RecoilSeconds` |
| 펀치에 몸이 안 실림 | `PunchLunge`, `PunchTorsoYaw`, `PunchLean` |
| 다운 포즈가 어색함 | `DownPosition`, `DownRotation`, `DownFallSeconds` |
| 글러브가 느리게 따라옴 | `RestResponsiveness` |

**코드 상수** (`CombatTuning.cs` / `FighterStats.cs`):

| 증상 | 노브 |
| --- | --- |
| 타격이 끈적함 / 너무 가벼움 | `HitStopClean`, `HitStopTimeScale` |
| 콤보가 느림 / 너무 빠름 | `ComboCancelFraction` (낮추면 빨라짐) |
| 펀치가 느림 | `FighterStats.PunchSpeedScale`, 또는 `PunchLibrary`의 각 펀치 `WindupTime`/`StrikeTime` |
| 후딜이 길어 답답함 | `FighterStats.RecoveryScale` |
| 카메라가 너무 흔들림 | `CameraShakeClean`, `CameraShakeTaken` |
| 맞을 때 화면이 너무 붉음 | `FightHud.DrawDamageFlash`의 `0.42f` |

> **정직한 메모**: 타격감은 제가 직접 느껴볼 수 없는 유일한 영역입니다. 위 수치는
> 복싱 타이밍과 게임 관례에서 뽑은 **출발점**이고, 정답은 직접 쳐보신 감각입니다.
> "어퍼컷이 가벼워요" 같은 말로 알려주시면 어느 노브인지 짚어드립니다.

### 목표: 파이트 나이트 챔피언 — 뭐가 남았나

솔직하게 짚어두면, **FNC의 타격감은 대부분 애니메이션과 에셋에서 나옵니다.**
전투 로직에서 나오는 게 아닙니다.

| FNC의 구성요소 | 지금 상태 |
| --- | --- |
| 풀바디 모캡 애니메이션 (무게가 실린 스텝·펀치) | ❌ **없음. 이게 가장 큰 격차** |
| 어떤 자세에서든 펀치로 블렌딩되는 전환 | ❌ 없음 (Mecanim 필요) |
| 물리 기반 피격 반응 (래그돌 블렌딩) | 🟡 절차적 반응만 (`PlayHitReaction`) |
| 아날로그 스틱 궤적으로 펀치 지정 | 🟡 터치 제스처로 같은 발상 구현 |
| 가까운 카메라·DOF·땀·변형 셰이더 | ❌ 없음 (렌더 파이프라인 작업) |
| 사운드 디자인 | ❌ 절차 생성 땜질 |
| 타이밍·사거리·스태미나·카운터·채점 로직 | ✅ **이미 있음** |

즉 **전투 로직은 그 수준을 받칠 준비가 돼 있고, 몸이 없습니다.** 그래서 다음
단계는 타격감 수치를 더 만지는 게 아니라 **캐릭터**입니다. 지금 캡슐로 모션을
평가하는 건 불가능하다는 판단이 맞습니다.

### 실제 캐릭터 넣기 — 현재 상태와 남은 작업

애니메이션 레이어(`FighterAnimation.cs`)는 작성되어 있습니다. **Animator Controller를
손으로 짤 필요가 없습니다** — 씬의 `BoxingBootstrap` 오브젝트에 클립 슬롯이 있고,
거기에 드래그하면 끝입니다.

설계상 세 가지를 보장합니다:

- **코드가 타이밍의 주인입니다.** 모든 클립의 재생 시간을 매 프레임 직접 지정합니다
  (펀치는 `Fighter.PunchProgress`, 자세·풋워크는 누적 루프 시계). Mixamo 클립 길이는
  우리 선딜/타격/후딜과 무관하므로, 클립이 타이밍을 정하면 사거리·카운터 창·채점
  가중치가 전부 틀어집니다. 이 방식이면 클립의 Loop Time이나 길이를 건드릴 필요도
  없습니다
- **루트 모션은 끕니다** (`applyRootMotion = false`). 위치는 `FighterMotor`가
  움직이므로, Mixamo의 **In Place 체크를 깜빡해도 문제없습니다**
- **실패해도 안전합니다.** 슬롯이 비었거나 모델이 Humanoid가 아니면 이 레이어는
  아무것도 하지 않고 기존 절차적 캡슐 리그로 돌아갑니다

#### 1. 슬롯 구성

클립 슬롯은 크게 세 묶음입니다.

**스탠스 / 발놀림 (루프, 슬롯당 1개)**

| 슬롯 | 설명 |
| --- | --- |
| `Idle` | 기본 파이팅 스탠스. **이 칸만은 반드시 채워야** 합니다 (비면 T-pose) |
| `Guard` | 가드 자세. 비워도 `GuardPose`의 IK가 글러브를 얼굴로 올립니다 |
| `Step Forward` / `Step Back` | 전진 / 후진 |
| `Step Left` / `Step Right` | 좌 / 우 사이드 스텝 |

움직임은 상대 기준(앞뒤 = 거리, 좌우 = 서클링)이라 두 축이 각각 클립 하나에
바로 대응됩니다. 네 방향을 **크기 비율로 섞기** 때문에 대각선으로 움직이면
전진과 사이드 스텝이 동시에 재생됩니다 — 큰 쪽 하나로 스냅되지 않습니다.

> 사우스포 세트는 "**어느 쪽으로 가 보이는지**" 기준으로 넣으세요. 오소독스를
> 미러링해서 만들면 좌우 스텝이 뒤집히므로, 미러한 *Step Left* 클립은 사우스포의
> `Step Right` 칸에 들어갑니다.

**펀치 (슬롯당 여러 개 — 하나가 랜덤으로 뽑힘)**

`Jab` / `Straight` / `Hook` / `Uppercut`. 각 슬롯이 배열이라 **+ 버튼으로 변형을
몇 개든** 넣을 수 있고, 펀치가 나갈 때마다 그중 하나가 무작위로 선택됩니다.
잽이 매번 똑같이 나오면 사람이 아니라 기계로 보이니, 같은 펀치에 다른 모션 2~3개를
넣어두는 게 가장 값싼 타격감 개선입니다.

각 변형에는 `Window`(시작·끝, 0~1)가 붙습니다. 클립의 **어느 구간을 쓸지**만
정하는 값이고 경기 타이밍은 바뀌지 않습니다.

- 펀치가 너무 급하게 보이면 끝값을 줄이세요 (기본 `0 ~ 0.7`)
- 콤보 클립을 쪼개 쓸 수 있습니다. `Body Jab Cross`는 왼잽 → 오른크로스라서
  **Jab에 `0 ~ 0.5`, Straight에 `0.45 ~ 1`** 로 같은 클립을 두 번 쓰면 됩니다

**반응 (슬롯당 여러 개)**

`Slip`(회피), `Down`(다운). 비우면 절차적 반응이 대신합니다.

#### 2. 아직 없으면 받을 것

| 받을 것 | Mixamo 위치 | 왜 |
| --- | --- | --- |
| **`X Bot.fbx` (캐릭터 본체)** | 상단 **Characters** 탭 → `X Bot` | ⚠️ **필수.** `X Bot@동작` 파일들은 전부 애니메이션만이라 몸이 없습니다 |
| `uppercut` | Animations | 펀치 4종 중 가장 자주 빠짐 |
| `taking punch`, `knocked out` | Animations | 피격·다운 (없으면 절차적 반응이 대신함) |

캐릭터는 Format **FBX for Unity**, Pose **T-pose**. 애니메이션은 **Without Skin**.

내용을 모르는 클립(`X Bot@Boxing`, `Boxing (1)` 등)은 Project 창에서 클릭하면
인스펙터 **아래쪽 미리보기 창**에서 재생해볼 수 있습니다.

#### 3. Unity에서 연결하기

1. 씬을 열고 Hierarchy에서 **`BoxingBootstrap`** 선택
2. **Boxer Model** 칸에 `X Bot.fbx`를 드래그
3. **Orthodox Clips** 를 펼치고 각 슬롯에 클립을 드래그. 펀치/반응은 배열이라
   먼저 크기를 늘리거나 **+** 를 눌러 칸을 만든 뒤, 그 안의 `Clip`에 넣습니다
   - ⚠️ **FBX 자체가 아니라 그 안의 클립**을 넣어야 합니다. Project 창에서 FBX 왼쪽
     화살표(▶)를 펼치면 나오는 항목 중 **삼각형 모양 아이콘**이 AnimationClip입니다
4. **Southpaw Clips** 는 비워둬도 됩니다 — `Idle`이 비어 있으면 아무도 사우스포를
   배정받지 않습니다
5. **Play** — 모델이 캡슐을 대체하고, 캡슐은 숨겨진 채 폴백으로 남습니다

모델 키가 안 맞으면 `Model Scale`, 바라보는 방향이 틀어졌으면 `Model Yaw Offset`로
맞추세요. 펀치마다 캐릭터가 점프하듯 튀면 `Hip Height Lock`(기본 1)을 확인하세요.

#### 4. 남는 한계

- **1인칭은 모델과 함께 쓸 수 없습니다.** FP에서는 내 몸을 숨기는데, 모델은 손도 몸의
  일부라 아무것도 안 보입니다. FPS가 쓰는 별도 팔 모델(viewmodel)이 필요한 문제이고,
  브로드캐스트 3인칭이 기본이라 당장은 보류합니다
- 머리 전용 피격 스냅은 모델에서는 빠집니다. 몸 전체 반동·기울기·다운 포즈는
  `BodyPivot`을 통해 애니메이션 위에 그대로 얹힙니다

## 9. 프로젝트 구조

```
Assets/Scripts/
├── Core/                       # 데이터 · 수치 (MonoBehaviour 아님, 순수 C#)
│   ├── FightEnums.cs           #   스탠스 / 손 / 펀치 / 부위 / 결과 / 상태 / 스타일
│   ├── PunchLibrary.cs         #   펀치 4종 정의 (데미지·스태미나·타이밍·사거리·관통·궤적)
│   ├── FighterStats.cs         #   파워/체력/스피드/스킬 → 전투 수치 변환
│   ├── BoxingStyles.cs         #   스타일 6종 배율 + 선호 거리/펀치 + 능력치 기반 추론
│   ├── CombatTuning.cs         #   전투 감각 상수 전부 (밸런스는 여기만 건드림)
│   ├── RoundRules.cs           #   라운드 길이·휴식·단계별 경기 거리·코너 회복·채점 상수
│   ├── FighterIntent.cs        #   브레인 → 파이터로 넘기는 "이번 프레임에 하려는 것"
│   └── HitEvent.cs             #   판정된 펀치 한 건
├── Fight/
│   ├── Fighter.cs              #   체력·스태미나·가드게이지, 펀치 상태머신, 피격 처리, 다운/KO
│   ├── FighterMotor.cs         #   CharacterController 풋워크 + 상대 자동 바라보기 + 링 경계
│   ├── FighterRig.cs           #   몸 전체 절차 애니메이션: 글러브·스탠스 반전·펀치 궤적
│   │                           #   + 몸 커밋·피격 반응·다운 포즈·스텝 셔플
│   ├── FighterAnimation.cs     #   실제 Humanoid 클립 재생 (Playables, 컨트롤러 불필요)
│   ├── Hurtbox.cs              #   머리 / 몸통 피격 볼륨
│   ├── TouchBrain.cs           #   터치 제스처 → FighterIntent (모바일 기본)
│   ├── PlayerBrain.cs          #   키보드·마우스 → FighterIntent (PC 테스트용)
│   ├── AIBrain.cs              #   스타일 기반 판단 + 경기 중 동적 스타일 전환
│   ├── FightCamera.cs          #   브로드캐스트 카메라(기본) + 1인칭, 흔들림/FOV 킥/푸시인
│   ├── ImpactFeedback.cs       #   히트스톱 + 카메라 흔들림 + 절차적 타격음(에셋 0개)
│   ├── Scorecard.cs            #   라운드별 집계 + 심판 3명 10점 머스트 채점 + 판정
│   ├── FightDirector.cs        #   라운드 상태머신(개시→라운드→휴식→판정), 이벤트 배선
│   └── FightHud.cs             #   IMGUI 디버그 HUD (임시, H키로 Full/Minimal/Off)
├── Bootstrap/BoxingBootstrap.cs    # 링·조명·양 선수·카메라·HUD를 코드로 구성
└── Editor/PrototypeSceneBuilder.cs # "The Fighter" 메뉴 → 씬 자동 생성
```

`Fighter`는 **무엇을 할지 결정하지 않습니다.** `IFighterBrain`이 매 프레임
`FighterIntent`(이동/가드/회피/펀치/조준)를 넘기고, `Fighter`는 그걸 실행만
합니다. 그래서 플레이어와 AI가 **완전히 같은 전투 코드**를 지납니다.

## 10. 개발 순서 — 모바일 출시까지

목표는 모바일 출시입니다. 순서의 핵심은 **터치 복싱이 재미있는지를 가장 먼저,
가장 싸게 확인하는 것**입니다. 그게 아니면 커리어·UI·아트가 전부 버려집니다.

- [x] **0단계 — 전투 프로토타입**
      이동/서클링, 펀치 4종, 양손 글러브 + 스탠스 반전, 가드 + 가드 게이지,
      회피, 머리/몸통 히트박스, 카운터 2종, 스태미나, 3-다운제 KO,
      스타일 6종 + AI 동적 전환, 히트스톱·흔들림·타격음
- [x] **1단계 — 터치 컨트롤 + 브로드캐스트 카메라 + 스탯 밸런스**
      `TouchBrain`(한 손가락당 한 역할 제스처), 중계 카메라, 스탯 비례 체력바,
      스피드/스킬 타이밍 분리, 가로 고정 + 60fps
- [x] **2단계 — 경기 규칙: 라운드와 판정**
      90초 라운드 + 12초 코너, 단계별 경기 거리(3~8R), 10점 머스트 3심 채점,
      만장일치/스플릿/다수/무승부 판정, 코너 회복(후반에 약해짐),
      3-다운제 라운드 단위, 공에 살아나기
- [x] **3단계 — 타격감 1차**
      피격 반응(머리 꺾임·보디 접힘), 명중 시 글러브 정지, 몸 커밋 모션,
      콤보 캔슬(반대 손만), 피격 화면 플래시, 펀치별 타격음, 다운 포즈,
      넉백 강화, 플레이스홀더 풋워크(스텝 셔플·호흡 바운스·무게 이동),
      HUD 모드 토글(H)
- [ ] **4단계 — 실제 3D 캐릭터 + 애니메이션 (다음)** ⬅ **지금 여기가 병목**
      캡슐로는 모션도 타격감도 평가가 불가능합니다. Mixamo로 리깅 캐릭터 +
      복싱 클립을 넣고 Mecanim으로 연결 (경로는 8절 끝 참고).
      애니메이션은 `Fighter`의 페이즈 진행률로 구동 — 코드가 타이밍의 주인
- [ ] **5단계 — 타격감 2차** 실제 모션 기준으로 재튜닝, 래그돌 블렌딩 피격 반응,
      가까운 카메라/DOF, 실제 타격음. 목표는 파이트 나이트 챔피언 급
- [ ] **5.5단계 — 경기 규칙 보강** 클린치, 코너 몰기, 심판 TKO 개입
- [ ] **(보류) 실기기 터치 검증** ⚠️ *기기가 생기면*
      맥·안드로이드폰이 없어 보류. 에디터 Device Simulator로 레이아웃만 검증 중.
      확인할 것 ① 제스처가 타이밍 게임을 버티는지 ② 1인칭 유지 여부
      ③ 엄지가 글러브를 가리는지. iOS 햅틱(Taptic)도 여기서
- [ ] **6단계 — 커리어 데이터 레이어**
      `CareerData` / `MatchGenerator` / `CareerConfig`,
      저장은 `Application.persistentDataPath`에 JSON
- [ ] **7단계 — 실제 UI** 홈 / 경기 제의 / 캐릭터(훈련·스탠스) / 스테이지 / 기록.
      IMGUI HUD를 여기서 걷어냅니다(화질·화면 점유 문제도 같이 해결). 한글 폰트 에셋 필요
- [ ] **8단계 — 무대 아트** 링/관중/조명, 무대 단계별 배경, 입장·세리머니 연출
      (캐릭터는 4단계에서 이미 들어감)
- [ ] **9단계 — 스토어 준비** 아이콘, 기기별 스크린샷, 연령등급,
      개인정보 매니페스트, TestFlight 베타, 심사

## 11. 알려진 제약

- **터치 컨트롤은 아직 실기기에서 검증되지 않았습니다.** 에디터 마우스
  시뮬레이션으로만 확인 가능한 상태이고, 1.5단계가 바로 그 검증입니다.
- **1인칭 글러브 위치와 엄지가 충돌할 가능성**이 남아 있습니다. PC에서는
  글러브를 화면 아래 가장자리로 내려 시야를 확보했는데(4절), 폰에서는 바로
  그 자리가 엄지 밑입니다. 실기기에서 확인하고 1인칭/3인칭을 결정해야 합니다.
- **Unity 에디터에서 컴파일 검증을 하지 못한 코드가 포함됩니다.**
  작성 환경에 Unity도 .NET 컴파일러도 없어서 구조 검사(괄호 균형, 타입 멤버
  교차 확인)까지만 했습니다. 에러가 나면 알려주세요.
- `Packages/`와 대부분의 `ProjectSettings/`는 저장소에 없습니다.
  Unity가 처음 열 때 기본값으로 생성합니다. **출시 전에는 커밋해야 합니다**(8절).
- HUD는 전부 영문입니다. Unity 기본 IMGUI 폰트에 한글 글리프가 없어서
  한글을 쓰면 네모로 깨집니다. 5단계에서 폰트 에셋과 함께 한글화합니다.
- 캐릭터는 캡슐+구 프리미티브입니다(의도적).
- 에디터 터치 시뮬레이션은 손가락이 하나뿐이라 이동과 펀치를 동시에 넣을 수
  없습니다. 제스처 인식 확인용입니다.
